# OnboardTrace · 引导流程验收台

面向产品 / 设计 / 法务三方协同改版新用户引导的**验收工作台**。同一份引导步骤有多个版本，
版本随设备、地区、用户选择动态命中；本台在模拟真实点击与键盘操作的同时，对每一步做全量留痕，
解决"只看最终截图无法知道跳过了哪个必要确认、无法复现某版本引导路径"的问题。

React 18 + TypeScript + Vite，零 UI 依赖（流程图为原生 SVG）。

## 启动

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 类型检查 + 生产构建
npm run test:scenarios  # 7 个引擎验收场景 / 42 条断言
npm run test:smoke      # jsdom 真实挂载：单步/撤销重做/刷新恢复/历史/重置（16 条断言）
```

## 能力对照

| 需求 | 实现 |
| --- | --- |
| 步骤版本 | 每步多个 `StepVersion`（产品/设计/法务，带发布日期、changelog、命中条件）；第一个条件为真者胜出，否则基线版本取最新发布。版本面板列出每个候选的"条件命中/不成立/基线兜底" |
| 条件分支 | 节点 `visible`（企业验证/邀请 vs 通知偏好）+ 出边 `when`（隐私授权后分流）；每条边每次求值都记录结果，流程图实线✓/虚线✗ |
| 返回修改 | 回到任意已过步骤：下游节点标记"已失效"、其写入的上下文**按键回收**、条件边重新求值；版本边界事件记录"vX 切换为 vY" |
| 中断恢复 | 手动中断 / 注入崩溃 / **刷新页面**三种来源；运行中的存档恢复时自动转"中断待恢复"并附 `session_recovered` 事件，从原节点继续 |
| 设备操作模拟 | 桌面/平板/手机三种机身；真实鼠标点击与键盘（`Enter` 确认、`Esc` 跳过、`Alt+←` 返回）；自动播放按拟人策略选择输入方式（桌面偏键盘、手机全点按） |
| 四种状态区分 | `未展示 unseen`（路径未到达）/ `主动跳过 skipped`（用户操作且事件含输入方式）/ `条件不满足 condition_failed`（到达但 visible=false，自动顺延）/ `中断待恢复 interrupted` |
| 运行控制 | 单步、自动播放（0.5–4×）、暂停、从任意节点重跑（流程图节点 ↺）、撤销/重做（120 步）、刷新恢复（localStorage）、重置 |
| 故障注入 | 提交失败（一次性，停留可重试）、慢加载（1.2s loading）、崩溃（中断待恢复） |
| 留痕 | 每条事件含序号、相对时间、runId、步骤、命中版本、条件边、输入方式（点击/键盘/自动）、上下文增量；可按 10 类筛选 |
| 可复现 | 完成的运行归档（配置、路径、版本、上下文、完整事件流），弹窗回放；验收脚本可"载入配置"手动复现 |

## 验收脚本（左下角，可在界面内直接跑）

1. **条件分支：企业线** — 企业节点确认、个人线节点 condition_failed、条件边留痕
2. **返回修改：个人线改企业线** — 下游失效、上下文回收、资料表单重判法务必填版
3. **版本边界：地区×设备矩阵** — 同一逻辑连跑 4 次，条款命中 cn-v1 / us-v4 / eu-dpa-v2 / mobile-v3
4. **必要确认拦截** — 欧盟隐私跳过被拦、漏勾被拦，两次 blocked 留痕，补齐放行
5. **中断与恢复** — 冻结/恢复后上下文与路径无损
6. **故障注入三连** — 慢加载、提交失败重试、崩溃恢复后完成
7. **从节点重跑** — 下游全部 invalidated、条件边重新求值、改选后再次完成

## 引擎设计要点

- `reduce(state, cmd) → { state, effects }` 为纯函数；慢加载等延迟以 `Effect` 描述交给外层计时，
  因此同一份引擎既能驱动 UI，也能在测试台里把副作用立即排空做确定性断言。
- 回退/重跑不删除历史：被废弃的结果转为 `invalidated` 而非 `unseen`，"曾经走过又作废"本身就是验收信息。
- 必要确认（步骤 `required`）与版本是否给跳过入口（版本 `skippable`）刻意分离：
  法务版本不可跳过时跳过尝试被拦截并归责到具体版本与 owner。

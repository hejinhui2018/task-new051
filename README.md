# OnboardTrace · 引导流程验收台

面向"产品 / 设计 / 法务分别调整同一组引导步骤"的验收场景：步骤多版本、条件分支、
返回修改、中断恢复，并在每次运行中记录**触发条件、可见步骤、用户选择与后续影响**。

React 18 + TypeScript + Vite，纯 TS 引擎与 React 解耦，可 headless 自测。

## 启动

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # 类型检查 + 生产构建
npm run test:smoke # 60+ 断言的引擎验收冒烟测试
```

## 四种步骤结局（路径地图与日志实时区分）

| 结局 | 含义 | 产生方式 |
| --- | --- | --- |
| **未展示 not-shown** | 本次路径不可达 | 分支绕开（如个人用户不见企业核验）或尚未走到 |
| **条件不满足 condition-failed** | 到达了但 gate / 版本可见条件为 false，自动绕开 | 如移动端不见通知开关、非欧盟不见 GDPR 版 |
| **主动跳过 skipped** | 步骤可见时点"跳过" | 可跳过版本；跳过"必要确认"额外打风险标记 |
| **中断待恢复 interrupted** | 可见后故障中断 | 网络故障；现场持久化，刷新也能原地恢复 |

## 功能

- **步骤版本**：每个步骤有 product / design / legal 各自的 v1/v2/v3，运行时按
  "固定版本 → 第一个 `visibleWhen` 满足"选择；可下拉固定任意版本（📌），
  返回/重跑再次进入时记录 `version-boundary`。
- **条件分支**：安全表达式（`&& || ! == != > >= < <=`、括号，无 eval），
  分支求值明细逐条进日志（命中/未命中）。
- **返回修改**：回到上一个已完成步骤，其后的步骤状态清空为"未展示"；
  改选分支后旧分支步骤自动消失。
- **中断恢复**：网络故障注入后步骤进入中断，`localStorage` 持久化，
  刷新页面点恢复可从中断步骤继续。
- **运行控制**：单步（→）、自动播放（1.1s/步，空格暂停）、暂停、
  从任意节点重跑（新 runId、保留前段）、撤销/重做（Ctrl+Z / Ctrl+Shift+Z）、
  刷新恢复、重置。
- **设备 / 输入模拟**：桌面/移动设备切换（参与 gate 求值）；
  鼠标 vs 键盘（Enter/Space）通道分别记录；移动端键盘焦点丢失故障会吞掉键盘提交。
- **故障注入**：网络中断、运行中版本漂移、双击/重复回车幂等去重、键盘焦点丢失。
- **重复运行**：同一画像再次运行产生 `repeat-run` 事件并累计完成次数。

## 验收画像

1. 中国·桌面·个人 —— 基线路径，通知步骤可见
2. 欧盟·移动·个人 —— GDPR 隐私 v2 必答、Cookie 必现、通知条件不满足
3. 美国·桌面·企业 —— 企业核验分支，绕开年龄确认
4. 欧盟·桌面·企业+邀请码 —— 邀请码分支与重复运行

## 代码结构

```
src/engine/
  types.ts       类型：步骤/版本/分支/结局/追踪/故障/运行态
  conditions.ts  安全条件表达式解析求值
  flow.ts        引导流程定义（10 步 × 多 owner 版本）+ 验收画像
  reducer.ts     纯函数状态机：进入/gate 绕开/提交/跳过/返回/重跑/中断/撤销重做
  persistence.ts localStorage 持久化（含撤销栈，刷新全量恢复）
  smoke.ts       headless 验收测试（9 大场景）
src/hooks/       store 持久化 + 自动播放 + 步骤草稿
src/components/   设备模拟器 / 路径地图 / 追踪日志 / 控制面板 / 运输条
```
